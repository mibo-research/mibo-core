# MIBO Core v1.0 — Pre-Wave-1 Execution Gate

**Scientific protocol version:** v1.0  
**Protocol DOI:** `10.5281/zenodo.21936410`  
**Planned Wave 1 start:** 1 September 2026

This record separates the already frozen **scientific specification** from operational facts that must be verified immediately before confirmatory collection.

**Rule:** No confirmatory Wave-1 output may be inspected before all applicable gates are closed. A failed gate postpones or narrows collection; it does not authorize retrospective alteration of the v1.0 protocol.

## A. Responsibility and readiness

- [ ] Principal Investigator confirms responsibility for Wave 1.
- [ ] Any delegated operations, data, technical, statistical, coding, or mirror roles are named.
- [ ] Dedicated storage and provenance paths are tested.
- [ ] Operational dry run completed without using confirmatory Wave-1 outputs.

## B. Institutional and legal/contractual status

- [ ] The applicable institutional process has been checked for the ethical status of the non-human-participant Core observations.
- [ ] Any required institutional determination is documented before collection.
- [ ] Provider Terms-of-Service / acceptable-use review is dated for every observation mode to be used.
- [ ] No observation mode is used if access or contractual conditions prohibit the planned procedure.

## C. Ecological Live configuration freeze

For each Core lineage:

- [ ] exact public service / plan / account tier recorded;
- [ ] displayed model or mode recorded;
- [ ] memory / personalization / custom-instruction state recorded;
- [ ] browsing/search/tool availability recorded;
- [ ] locale/language/site recorded;
- [ ] capture procedure verified.

## D. Paired Live–Frozen technical lock

Before paired collection:

- [ ] exact Paired Live Reference ID recorded;
- [ ] exact Frozen Reference ID recorded;
- [ ] version-pinning / identity evidence archived;
- [ ] generation and reasoning controls matched as required;
- [ ] tools, retrieval, web, files, and memory disabled for the environment-closed module;
- [ ] final comparability class recorded;
- [ ] at least two eligible paired lineages confirmed, or the paired hypothesis set is prospectively reduced/classified as not assessed under the SAP.

No pair may be promoted after confirmatory outputs are inspected.

## E. Instrument and coding implementation

- [ ] SHA-256 hashes of administered query forms match the v1.0 instrument.
- [ ] Query ordering/randomization implementation checked.
- [ ] Coding dry run completed on non-confirmatory material.
- [ ] Entity and Source Table construction tested.
- [ ] AI-assisted coding configuration, if used, is fixed and validation responsibility recorded.
- [ ] Locked human reference-set procedure is ready before confirmatory AI coding.

## F. Statistical implementation

- [ ] Analysis code maps exactly to v1.0 outcomes and decision rules.
- [ ] Simulation/implementation check completed on synthetic data.
- [ ] Software environment and package versions recorded.
- [ ] Random seeds / reproducibility mechanism fixed where applicable.
- [ ] No simulation-driven change to v1.0 thresholds or hypotheses has been made without a prospective amendment.

## G. International calibration

When the calibration wave is run:

- [ ] at least three eligible sites are registered for the primary site-facet analysis, or the relevant hypothesis is classified according to the SAP;
- [ ] site configuration records are complete;
- [ ] mirror-kit version/hash verified;
- [ ] site leads attest to protocol compliance.

## H. Final authorization

- [ ] All applicable items above are closed.
- [ ] Any inapplicable item is marked N/A with a reason.
- [ ] Configuration Freeze Record is signed and time-stamped.
- [ ] Principal Investigator authorizes confirmatory Wave-1 collection.
