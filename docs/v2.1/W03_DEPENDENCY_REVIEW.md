# W03 registration dependency — 7 November 2026

During implementation the shared checkout advanced to an independent W03
URL-string analysis registration. Its changes were preserved, not reverted,
amended or republished. The initial package excluded that independent work;
the owner-directed update now includes unchanged reference copies/dependency
code alongside a separately prepared v1.1 amendment draft.

Source: [immutable W03 registration](https://github.com/mibo-research/mibo-core/blob/30e48170f7387002e506baabd36884f12cc7a250/docs/analysis/W03-URL-variation-v1.0/REGISTRATION.md).
Its public raw copy was independently fetched (HTTP 200, 8,009 UTF-8 bytes),
SHA-256 `1b0079041e0b3e344ec140e160745e9725be0022517bff41cbdada4b41ba1f3c`.

The registration explicitly fixes W03/JP01/ACI, 1–3 December 2026 UTC,
four lineages × 24 forms × 10 = 960 initial requests, an I03 EN/JA subset of
80 intended slots, v2.0.1 configuration/source/manifest bindings, and
W03-minus-W02 comparisons. It states that its deterministic derivative
analysis does not change the Core panel. Its optional AI supplement requires
a separate prospective coding freeze and makes no human-validity claim.

Therefore a v2.1 three-lineage W03 would not silently satisfy that registration:
it would have 720 total and 60 I03 slots, a new version-specific manifest and
new freezes, with a separate baseline policy. No 960-to-720 or 80-to-60
denominator replacement has been performed.

At initial review, two routes were offered:

1. Preserve that W03 registration and use W04 (5–7 January 2027 UTC) or a later
   original wave for v2.1. This was the least-disruptive proposal at that review;
   it is **not** authorization to run the old four-series W03 collector.
2. Use v2.1 for W03 only after separately amending the W03 derivative plan and
   publishing that amendment prospectively. Specify the changed intended panel,
   I03 subset, configuration hashes and comparison policy explicitly. This
   preparation does not publish or authorize that separate change.

The owner subsequently chose route 2: three-series W03 and preparation of the
analysis amendment. `OWNER_DECISION_W03_20261107.json` records the reply without
creating publication or API authority. The new draft has 720 full-design
requests and 60 I03 slots in six cells; historical v1.0 stays byte-identical.

The v2.1 protocol JSON now records W03 as the selected effective wave and the
local amendment-draft path, but retains null publication identifier/timestamp.
Final loading still requires a genuinely published prospective W03-amendment
registration and Core registration. A later explicit owner reply approved
W03 as the new STD baseline, exclusion of W02 from current primary comparison,
no automatic baseline replacement and separate W04 calibration. The current
draft/library implement that local policy without computing W02 contrasts.
No public registration, new freeze, signature or API permission is fabricated.
