# W01後の収集処理点検とW02への修正

2026-10-10。点検対象はW01終了処理を含むcommit `1b12602cb311d14659a6b4e290db03d3222b71d0`。この記録は公開可能なソフトウェア検証であり、私有W01原記録の監査報告ではない。

## 確認した問題と修正

| 問題 | 修正 | 合成試験で確認する挙動 |
|---|---|---|
| 再起動で系統停止や待機状態を失う | 保存された失敗・逸脱から状態を復元 | 環境不一致・障害後の停止を維持し、429等の待機を短縮しない |
| failure保存とretry-link保存の間で中断する | 登録規則から同じ再試行判断を復元 | 同じID・期限でリンクを追記し、最大2回を維持する |
| 送信・保存途中の中断を処理済みと認識できない | アダプター呼出前のdispatch意図、未完保存検知、排他的な同期保存 | 未確定dispatch、孤立raw、破損metadataがあれば自動再送せず停止する |
| 版を変えると同じ波・系統を並行実行できる | 波・系統単位の版横断排他、同版保存領域の排他、移行前のdispatch確認 | 同じ系統の重複実行と同じ保存領域の競合を停止し、異なる系統の正当なスコープを区別する |
| 連番なら実行順の入替えを見逃す | 凍結入力から再生成し、IDと登録実行順を照合 | W01・W02とも順番の付け替えを拒否する |
| Retry-AfterのHTTP日時形式を無視する | 日時をUTC待機秒数へ切り上げ変換 | 提供側の長い待機を守り、登録窓の延長や最短間隔の短縮をしない |
| 保存件数と解析可能性が混同される | 本文を評価しない波別監査 | 全予定枠を分母とし、HTTP証拠、2xx capture、未完保存、異版重複、再試行違反を区別する |
| W01専用終了処理を通常波に適用できない | 凍結入力を指定する汎用終了処理 | 960/1,120枠を区別し、実行停止・原記録整合・人署名を確認して封印する |

dispatchは送信前の意図であり、サーバーの受信証明ではない。監査の送信数はHTTP応答から確認できる下限である。技術的capture候補は回答内容の有効性・独立性・比較可能性を認定しない。窓内開始・窓後完了は注記し、新しい科学的除外規則を加えない。

同期保存はファイルと新設ディレクトリの親を含めて`fsync`する工学的対策である。合成試験は呼出・状態復元の挙動を確認する。電源断、実VMでの復元、基盤ストレージの耐久性は実験しておらず、完全な障害耐性を保証しない。

同じ版の保存領域を異なる承認範囲のcollectorが同時に使うことは、記録生成の競合を避けるため明示的に拒否する。異なる版・異なる系統の排他は分離する。同じcollector内では系統別の待機を扱える。採用するW02の参加経路とサービス構成で、開始前にVM上の運用を検証する。

## 科学的条件と残る作業

最終ローカル統合検証は `python -m unittest discover -s automation/tests -v` の209試験が成功した。追加回復18、波監査21、汎用終了21、Retry-After4の限定試験は別担当による再実行でも成功した。W01の実行計画生成と構造・厳密整合検証、Core v2の合成W01 1,120行・W02 960行の凍結入力との整合検証も通過した。試験では実サービスへ要求を送信していない。

CIで判明した試験側の管理者権限への依存は、所有権変更と権限確認の明示的な模擬で除いた。実際の終了処理のroot要件は保持し、非rootが署名・書込前に拒否される回帰も追加した。ローカル環境はユーザー切替を許可しないため、実非root環境の確認はGitHub CIの結果で判定する。

W01の2.0.1〜2.0.4はAgent API移行・系統別参加・GoogleのPriority申請とStandard復帰を扱うプロトコル改訂である。公開の改訂承認と私有の実行承認を区別する。旧版に未確定の要求があれば移行して再送しない。

W02は通常波960枠。W01の校正窓とW02の48時間窓は異なるため、単にWBを除外して波間比較を行わない。モデル・要求profile・プロトコル版・窓を記録し、登録された比較可能性と解析基準を適用する。欠測を埋める収集、代替モデル、内容を理由とする再試行は行わない。

実W01の予定一覧・failure・metadata・raw・逸脱・封印を私有環境で監査し、記録で裏付けられる原因と未確定な原因を分ける。W02の実行経路は [開始前の確認案](W02_READINESS_DECISION_DRAFT.md)、監査は [監査手順](W02_AUDIT_TOOL.md)、終了は [終了手順](W02_CLOSE_RUNBOOK.md) に従って具体的な入力と証拠を整える。VM適用、実サービス準備、人によるhash対応の実行承認、独立バックアップの復元確認は別途実施する。
